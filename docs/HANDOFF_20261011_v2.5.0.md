## 3. 2026-10-11 확인 사항

- **강제 종료 대상 정정**: Google 먹통 초기화는 `com.google.android.tts`(ML Kit BASIC → tts 안의 SODA, logcat 확인) — 앞선 답변의 com.google.android.as 는 잘못. 회복 조건은 tts 프로세스 재시작뿐(18분 기다려도 같은 PID 회복 안 됨, SttConstants.kt 기록).
- **공급 속도가 결과 폴더·CSV 이름에 없다**(START 도 같음) → 목록은 `<날짜>_<FEED>` 폴더로 구분.
- **sherpa 오프라인 엔진은 공급 속도를 쓰지 않는다**(최대 속도 디코딩) → REALTIME 만 돌린다(Q43).
- 동시 실행 안전성: BatchRunner 는 run() 안의 지역 변수로만 상태를 갖고, 전사기·VAD 는 배치마다 새로 만든다. 공유 가변 상태 없음.

## 4. 남은 일

### 4-1. 바로 할 일 (PC·실기기)
1. PC: `bash _apply_v2.5.0/apply_v2.5.0.sh` → (아직이면) `bash tools/download_stt_models.sh aar` → Gradle Sync·Run → `git push`
2. 견본 목록을 휴대폰에 넣기: `docs/stt_plan_samples/plan_kr_en_app_REALTIME_VAD21.csv` → 휴대폰 `Documents/stt_plan/`(MTP 복사 또는 `adb push … /sdcard/Documents/stt_plan/`)
3. 앱 엔진 모델 15종(견본은 15종 모두 씀)이 휴대폰에 있는지: `bash tools/download_stt_models.sh all`(약 5.6 GB) — [목록 실행] 점검이 빠진 모델을 알려 준다
4. 짧은 시험 먼저: 화면에서 작업 3~4개(오프라인 1 + 스트리밍 2, kr)로 [목록 실행] → 결과 폴더·`_plan_progress.csv`·[중지] 두 가지·이어 하기 확인
5. 본 실행: 입력 `Documents/input_sound`, 새 출력 폴더, 견본 525 작업, 충전기 연결
6. Google 2종은 개별 START(EPD A안, 입력 폴더를 35세션 안으로 나눠서)

## 5. 주의 사항
- 목록 실행 결과의 시간·자원 열은 동시 실행으로 섞인 값(run_meta `parallel_jobs=3`) — 전사 글자 비교에만 쓴다

- "지금 바로 중지" 는 지금 파일이 끝나야 멈춘다
- 이 작업 환경: Maven·alphacephei.com·Hugging Face 차단, GitHub 가능. 컴파일 확인은 PC jar + 새 R 스텁(scratchpad)으로 했다
