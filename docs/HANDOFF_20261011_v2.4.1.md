## 3. 2026-10-11 질문 답변 기록

### 3-1. S22 Ultra(SM-S908N) vs S25 Ultra — 전사 능력 차이
- **앱 안 엔진(sherpa 13종·Vosk 2종)**: 같은 모델 파일·같은 arm64 라이브러리·같은 앱 코드(VAD·노이즈 저감·조각 나누기)라 결과 글자는 같아야 한다. 이론상 CPU 명령어(SIMD) 경로 차이로 부동소수점 끝자리가 달라져 드물게 다른 토큰이 나올 수 있으나 크기는 작다.
  - 근거: 같은 앱 클래스로 1.13.7 ↔ 1.13.8(onnxruntime 판도 다름) 8종 결과 글자가 같았다. 스트리밍은 REALTIME(공급이 따라감)과 D10(공급이 3배 밀림)의 결과 글자가 같았다 → 기기가 느려도 글자는 같다(공급을 버리지 않는 구조).
  - 확인 방법: 두 기기에서 같은 모델·조건·음원으로 돌려 TXT 를 그대로 비교(diff). 같으면 앱 엔진은 기기 하나로 측정해도 된다.
- **Google 엔진 2종(ML Kit Basic, 플랫폼 on-device)**: 모델이 앱 밖(Google 음성 서비스)에 있어 **기기마다 판이 다를 수 있다** → 결과가 다를 수 있다. run_meta `recognition_services` 에 판이 남는다(S22: `com.google.android.tts(googletts…20260817…)`, `com.google.android.as(…)`). 비교하려면 두 기기의 Google 앱·음성 서비스 판을 맞추거나, 판을 결과에 함께 적는다.
- **간접 영향**: 메모리 부족으로 앱이 강제 종료되거나 Google 세션이 멈추면 빈 결과가 생긴다(평가기는 실패도 오류로 채점) — 전사 능력이 아니라 실행 실패로 구분해 본다.

### 3-2. "목록으로 줄 세워 한 번에 실행" — 설계 제안(미구현, 사용자 결정 대기)
- 지금은 START 1번 = 모델 1개 × 조건 1개. 제안 기능은 "실행 목록(작업 여러 개)"을 받아 차례로 돌린다.
- 작업 1개 = 언어 · 모델 · 공급 속도 · 노이즈 저감 · VAD 엔진·프리셋(·Custom 값) · 구간 처리 · EPD. 입력·출력 폴더는 목록 전체 공통.
- 동작: 작업마다 지금 START 와 같은 배치를 돌리고 결과 폴더·CSV 이름도 같다. 이미 끝난 작업(결과 CSV 행 수 = 입력 수)은 건너뛰어 이어 하기. 작업 사이 쉬기(발열 `thermal` 이 NONE 이 될 때까지 또는 N 초). Google 작업은 세션 한도(약 35) 때문에 목록 끝에 몰고, 한도 경고가 나오면 멈춤.
- 목록 형식 후보: (A) 화면에서 "지금 설정을 목록에 추가" (B) 텍스트 파일 `Documents/stt_plan/*.csv` — 한 줄 = 작업 1개, 열: `model,lang,feed,ns,vad,seg,epd`(값은 화면 이름 대신 결과 폴더에 쓰는 토큰) (C) 둘 다. 자세한 예시는 같은 날 채팅 답변 참고.
