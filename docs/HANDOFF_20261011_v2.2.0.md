## 3. 검증 근거(이 작업 환경)

- GitHub 릴리스의 `sherpa-onnx-v1.13.7-linux-x64-jni` + 앱 AAR 의 `classes.jar` 로 **앱과 같은 Kotlin API** 를 리눅스에서 실행할 수 있다(`scratchpad/jvmtest`, 시험용 `android.content.Context`·`android.util.Log` 대체 클래스).
- 휴대폰 시험 음원(`Documents/input_sound/kr/{customer,friend,vLog}/01.wav`)으로 실행:
  - Nemotron 560 ms: 3개 모두 정상, 토큰 기반 글자에 띄어쓰기 정상. 앱 클래스 `SherpaStreamingTranscriber` 로 D10·REALTIME+SEG10 실행 확인.
  - Cohere int8: customer·friend 에서 반복·영어 섞임, 조각 길이를 바꿔도 해결 안 됨(릴리스 노트 4장).
- `libsherpa-onnx-jni.so`(arm64) 문자열: 다국어 NeMo transducer 의 `prompt_index`·언어 처리 코드, Cohere 지원 언어 목록(ko 포함) 확인 → PR #3671 이 1.13.7 에 들어 있음.

## 4. 남은 일

### 4-1. 바로 할 일 (2-2 마무리)
1. PC: `bash _apply_v2.2.0/apply_v2.2.0.sh` → `git push`
2. `bash tools/download_stt_models.sh nemotron3.5-560ms` → `/sdcard/Documents/stt_models/` 확인
3. Android Studio Run(2.2.0) → Model "Nemotron 3.5 streaming 560ms" → Feed REALTIME 으로 kr 음원 실행 → Logcat `[D][sherpa-stream]`·`[D][stt]` 확인
4. `first_result_ms`·`tail_ms`·`feed_stall_ratio`, 메모리·발열 기록. D50 / D20 에서 공급 정체 여부
5. PC 의 Nemotron(320 / 560) 결과와 같은 음원으로 CER/WER 비교, 지연 2종 비교
6. Cohere: PC(transformers) 결과로 int8 품질 문제인지 확인 → 넣을지 다시 결정

### 4-2. 2-3
- Zipformer KO(offline/streaming), SenseVoiceSmall, Moonshine KO — `commercial=conditional` 표시
- Vosk small ko 0.22 / en-us 0.15 (`com.alphacephei:vosk-android:0.3.75`)
- 스트리밍 Zipformer 는 이번 `SherpaStreamingTranscriber` 의 공급·계측 틀을 그대로 쓸 수 있다(transducer). 띄어쓰기 문제도 같은지 확인할 것

## 5. 주의 사항
- **sherpa 스트리밍 결과 `text` 는 한국어 띄어쓰기를 지운다** → 반드시 토큰으로 만든다. 새 스트리밍 모델을 붙일 때도 확인
- Cohere int8 은 끝의 0 값 무음·문장 이어 붙이기에 약하다(앱의 구간 이어 붙이기와 충돌 가능)
- 모델 폴더는 공용 `/sdcard/Documents/stt_models`('모든 파일 접근' 필요). 앱 전용 폴더에 adb 로 넣지 않는다
- 이 작업 환경: Google Maven·Maven Central·Gradle 배포·PyPI 는 막혀 있고, **GitHub 릴리스 내려받기는 된다**(모델·리눅스 JNI). Gradle 빌드는 PC 에서
- PC 연결 폴더에서 8단계 이상 깊은 파일은 읽기(stage) 불가·쓰기는 가능 → 깊은 소스는 크기 비교 + 적용 스크립트의 내용 비교로 확인
- Kotlin 블록 주석 안에 `*/`·`/*` 금지, `abiFilters` 는 네이티브 중복을 막지 못함(`packaging.jniLibs.excludes`)
