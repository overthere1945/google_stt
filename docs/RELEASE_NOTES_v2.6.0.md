# 릴리스 노트 — google_stt v2.6.0

- 배포일: 2026-10-12
- 이전 판: 2.5.0 (versionCode 9) → **2.6.0** (versionCode 10)
- 판 번호 규칙: Major.Minor.Patch (Semantic Versioning)
- 이번에 Minor 를 올린 이유: 목록 실행에 기능을 더했고(이어 하기 창·기록 파일·동시 작업 수 선택) 기존 START·result.csv 열·진행 기록 형식은 그대로다. v2.5.0 진행 기록으로 그대로 이어 갈 수 있다.

## 1. 추가 (Added)

1. **폴더 기억 + 이어 하기 창**(사용자 결정 Q44) — 고른 입력·출력 폴더를 저장하고, 앱을 다시 열 때 권한이 남아 있으면 되살린다.
   - 프로세스가 새로 시작됐을 때 마지막 목록의 출력 폴더에 끝나지 않은 목록이 있으면 "DONE x / 전체 y — [이어서 실행]" 창을 띄운다.
2. **목록 사본 자동 저장**(Q45) — [목록 실행] 때 목록을 출력 폴더 `_plan.csv` 로 남긴다. 결과와 그 결과를 만든 목록이 한곳에 있고, 이어 하기 창이 이 파일을 읽는다.
3. **꺼진 이유·메모리 기록**(Q46)
   - 앱을 다시 열 때 지난 종료 기록(`ApplicationExitInfo`: LOW_MEMORY·CRASH_NATIVE·SIGNALED 등, 꺼질 때 PSS/RSS)을 화면 로그에, 목록 실행 도중이었으면 `_plan_exits.csv` 에도 남긴다.
   - 실행 중 30초마다 휴대폰 남은 메모리·시스템 기준선·메모리 부족 여부·앱 PSS·발열·돌고 있는 작업을 `_plan_memlog.csv` 에 덧붙인다.
4. **동시 작업 수 선택**(Q47) — 목록 영역에 1·2·3 선택(기본 3, 저장됨). run_meta `parallel_jobs` 도 그 값.
5. **끝나지 않은 결과 숨기기**(Q48) — 작업은 `_<결과 폴더>` 에 쓰고 DONE 이면 원래 이름으로 바꾼다. PC 평가기는 `_` 로 시작하는 폴더를 건너뛰므로 반쪽 결과가 채점에 섞이지 않는다.
   - 돌기 전에 같은 이름으로 보이는 예전 반쪽 폴더(v2.5.0 에서 끊긴 작업 등)는 지우지 않고 `_stale_<이름>_<시각>` 으로 비켜 둔다. 이름 바꾸기에 실패하면 그 작업은 FAILED(다음에 다시).
6. **메모리 부족 시 동시 작업 줄이기 제안**(Q49) — 목록 실행 도중 메모리 부족으로 꺼졌으면 이어 하기 창의 기본 버튼이 "동시 작업 N-1개로 줄여 이어 하기"다(사용자가 확인, 1 아래로는 줄이지 않음).
   - 메모리 부족 종료를 LOW_MEMORY 로 보고하지 않는 기기(`isLowMemoryKillReportSupported = false`)에서는 SIGNALED + 신호 9 도 메모리 부족으로 본다.

## 2. 바뀐 점 (Changed)
- `BatchRequest.runDirPrefix`(기본 "") · `ResultStore.saveResult(…, dirPrefix = "")` — START 는 예전과 같다.
- START 도 고른 폴더가 다음 실행 때 되살아난다(권한이 남아 있을 때).
- 목록 제목 "목록 실행 (오프라인 엔진은 동시에 1개)" + "동시 작업 수" 선택.

## 3. 알려진 제한
- 결과 CSV(`<엔진>_<조건>_result.csv`·`_run_meta.csv`)는 접두어 없이 쓴다 — 끝나지 않은 작업의 CSV 도 보인다. 평가는 TXT 모드로 한다.
- 이어 하기 창은 프로세스가 새로 시작될 때만 뜬다(같은 프로세스에서 뒤로 가기로 멈춘 뒤에는 [목록 실행] 으로 이어 간다).
- 삼성 등 일부 기기는 메모리 부족 종료를 다른 이유로 남길 수 있다 — `_plan_memlog.csv` 의 마지막 줄들로 함께 판단한다.
- SAF 폴더 이름 바꾸기·"wa" 덧붙이기는 실기기에서 확인이 필요하다.
