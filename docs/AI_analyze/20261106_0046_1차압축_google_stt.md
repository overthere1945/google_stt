## 4. WP2 에서 정한 구현 세부(설계 문서에 없던 것)
- **모델 수는 19개**(sherpa 16 + Vosk 2 + ML Kit 1). 문서의 "20개" 는 오기. kr 13 + en 15 = 616 계산은 맞다.
- **내려받는 VAD 자산은 4개**(Silero·pyannote·FSMN·FireRed). TEN 은 `.so` 를 APK 에 넣으므로 자산이 아니다. 문서의 "VAD 5" 는 엔진 수.
- `ModelSpec.family` 는 설계대로 String, 값은 `ModelFamily` 상수. zipformer 한국어·영어는 같은 "zipformer" 이고 구분은 `langSupport` 로 한다(WP5 어댑터에서 분기).
- `ModelSpec.files`(역할 → 경로) 를 넣었다(FR-02-01 의 "파일 목록"). STT 자산의 파일 목록은 여기서 자동 생성.
- `ArchiveType.NONE` 자산은 `url` 이 공통 앞부분이고 파일마다 `url/pathInArchive` 를 받는다(FSMN·FireRed 는 파일 2개).
- 매니페스트 JSON 은 `org.json` 으로 읽는다. JVM 시험용으로 `testImplementation org.json:json:20260814` 추가(APK 미포함).
- `AppError` 는 `domain/AppError.kt` sealed class. 오류 종류는 쓰는 Task 에서 추가(현재 `ManifestCorrupt` = E-AS-09).
- `LangPlan` 에 `skipped`(건너뛰기로 기억한 폴더) 필드 추가. `plan(rootPath, children, memory)` 의 rootPath 는 SAF 문서 ID(경로 판정·기억 키 겸용).
- 도메인에서는 `ui.VadSelection` 대신 `VadSetting` 을 쓴다(구간 처리는 `RunOptions.seg`). `SegMode` 는 `domain/vad/SegmentPacker.kt` 의 것을 재사용.
- `RunOptions.effectiveFor(runtime)`: 오프라인 Feed 없음, ML Kit REALTIME 고정, EPD 는 ML Kit·엔진별 최대 길이에서만. 조합 생성기가 이 값으로 중복을 합친다.
- `NsChoice(folder)` 는 조건 이름 조각만 가진다(알고리즘 설정은 engine/denoise). `EpdChoice(config)` 는 `EpdConfig` 를 가진다.
- `ComboResult.excluded` 는 `Pair<Job,String>` 대신 `Excluded(lang, model, count, reason)`.
- 측정값: Vosk zip — ko 86,914,329 B(sha256 eea36124…), en 41,205,931 B(30f26242…). pyannote tar 6,958,444 B(24615ee8…).

## 5. 남은 WP2 작업과 계획
### T2-6 PlanCsv·PlanProgress (`domain/plan/`)
- `PlanCsv`: v3 `plan/PlanModels.kt` 의 parse/format 을 이식. 행 자료형은 `PlanRow(lang, model, feed, vad, seg, lineNo)`.
  `toJobs(rows, langPlan, base: RunOptions)` — 언어 폴더 이름·모델·feed(`NONE` 추가)·VAD 고정 프리셋·seg 를 해석, 오류가 하나라도 있으면 불러오지 않음(E-CSV-01). `fromJobs(jobs)`.
