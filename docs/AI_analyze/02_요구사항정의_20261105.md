## 2. 목표와 범위

### 2-1. 목표
휴대폰 안에서 **엔진·모델 × VAD 조건 × 언어(kr/en)** 의 모든 조합을 사람이 개입하지 않고 끝까지 돌려, 서버 실행기와 같은 폴더 구조·같은 CSV 로 결과를 남기는 평가 앱.

### 2-2. 범위 안(In)
- 파일 배치 전사(입력 폴더 선택 → 언어 자동 → 조합 자동 생성 → 자동 다운로드 → 자동 실행 → 결과 저장).
- 엔진 11계열(1단계 3-4 카탈로그) + Google ML Kit Basic. VAD 5종 22 프리셋 + CUSTOM.
- 모델·VAD 자산 다운로드·검증·관리.
- 예상 소요 시간, 진행률, 중지/이어 하기, 크래시 복구, 발열 대기.
- 노이즈 저감·EPD·Feed 는 "사용 안 함" 기본으로 유지(D4).

### 2-3. 범위 밖(Out)
- 마이크 실시간 입력, WER/CER 채점(PC 평가기가 담당), 클라우드 엔진, iOS.
- whisper.cpp 통합 여부는 3단계 검증 뒤 결정(이 문서는 자리만 둔다: FR-02-06).
- Google Play 배포 요건(내부 평가용).

## 3. 용어
| 용어 | 뜻 |
|---|---|
| 조합(Job) | (언어 폴더, 엔진·모델, VAD 조건, 구간 처리, Feed) 1개 = 결과 폴더 1개 |
| 조건(condition) | `[NS_<ns>_]<VAD 프리셋 또는 NOVAD>[_SEG10][_EPD_…]` |

| 자산(asset) | STT 모델 패키지, VAD 모델 파일(ONNX·cmvn·mvn), 네이티브 라이브러리 |
| 온디바이스 증명 | 추론 구간에서 앱의 네트워크 송수신이 0 임을 계측으로 보이는 것 |

## 4. 사용 시나리오(주 흐름)
1. 앱 실행 → 저장공간·권한 점검(알림 권한, 폴더 권한).
2. 입력 폴더(`Documents/input_sound/scarlett`) 선택 → 하위 폴더 `en`·`kr` 자동 판정, 모르는 폴더는 묻고 기억(D9).
3. 출력 폴더 선택 또는 새로 만들기.
4. 엔진·모델(다중 선택), VAD 조건(다중 선택), 구간 처리, Feed/NS/EPD(기본 "사용 안 함") 선택.
5. 조합 미리보기: 개수, 언어 전용 모델 자동 제외 내역, 필요한 자산 목록·총 용량·부족한 자산, **예상 소요 시간**.
6. [다운로드 후 실행] → 부족한 자산을 받고 해시 검증 → 바로 실행(Foreground Service).
7. 실행 대시보드: 현재 작업, 진행률, 남은 시간, 메모리·발열, 로그. [중지: 지금 / 이 작업 끝나고].
8. 끝나면 요약(성공·실패·건너뜀) 표시. 결과는 PC 에서 `adb pull` 또는 MTP 로 가져가 평가기로 채점.
9. 앱이 꺼졌다 다시 열리면 이어 하기 제안(끝난 작업 건너뜀).

## 5. 기능 요구사항(FR)

### FR-01 입력·언어 자동
| ID | 우선 | 요구 | 수용 기준(AC) |
|---|---|---|---|
| FR-01-01 | M | SAF 로 입력 폴더를 고르고 재귀적으로 음원(mp3, wav, m4a, flac, ogg, aac, mp4, wma, opus)을 수집한다 | `input_sound/scarlett` 선택 시 en 30 + kr 24 = 54개 수집 |
| FR-01-02 | M | 입력 폴더 바로 아래 하위 폴더 이름으로 언어를 판정한다. 낱말: ko ← kr·ko·kor·korea·korean·한국어, en ← en·eng·english·영어; 같거나 `_<낱말>` 로 끝남(서버 `INPUT_LANG_WORDS` 와 동일) | `en`→영어, `kr`→한국어, `Customer_Service_KR`→한국어 |
| FR-01-03 | M | 하위 폴더가 모두 판정 불가이고 입력 폴더 경로 자체로 판정되면 그 언어로 전체를 돌리고 결과 폴더를 나누지 않는다(서버·v3.0.0 과 동일) | `input_sound/kr` 선택 → `<출력>/<엔진>_…` 바로 아래 |
| FR-01-04 | M | **(D9)** 모르는 폴더는 실행 시작 전 대화창에서 한국어/영어/건너뛰기를 고르게 하고, 폴더 전체 경로(SAF 문서 ID) 로 기억한다. 기억한 값은 미리보기·로그에 "기억한 값" 으로 표시하고 "기억 지우기" 를 제공한다 | `misc` 폴더에서 한 번 고르면 다음 실행에 묻지 않음 |
| FR-01-05 | M | 음원이 없는 언어 폴더는 건너뛰고 로그에 남긴다 | 빈 폴더가 실행을 중단시키지 않음 |
| FR-01-06 | S | 입력·출력 폴더와 마지막 선택을 저장해 다음 실행 때 되살린다(권한이 남아 있을 때) | 재시작 후 폴더 표시 유지 |

## 6. 통일 CSV v2.0(74열) 매핑 규칙(D10)

| D. 환경 | `device`=cpu, `device_name`=SoC·기기 모델, `compute_type`=int8/fp32(모델별), `workers`=동시 work 수, `cpu_percent_avg`·`cpu_time_sec`·`rss_peak_mb`=앱 프로세스 계측(PSS→MB), GPU 3열 공란, `host_id`=`<기기모델>/<SoC>`, `model_load_sec`(첫 행), `warmup_row`(Google warm-up 행만 1) | |

## 8. 제약과 가정
- Gradle 빌드·실기기 실행은 PC3 Android Studio 에서 사용자가 수행(Claude 환경은 Google Maven 접속 불가).
- 회사망은 HTTPS 검사 → 휴대폰 다운로드는 외부망(D12) 또는 PC 다운로드 후 가져오기(FR-05-04).
- sherpa-onnx 1.13.8 정적 AAR 유지가 기본. 2.0.1 업그레이드는 3단계 검증 뒤 별도 Minor 판.
- Google ML Kit Advanced 는 S24 Ultra 미지원 칩셋이라 범위 밖.
- 결과 채점은 PC 평가기가 담당하므로 앱은 정답지와 WER/CER 을 다루지 않는다.

## 9. 3단계(기술 타당성 검증)로 넘길 항목
1. AGP 9.3.1(built-in Kotlin) + Compose 컴파일러 플러그인 설정, Compose BOM·Material 3 판.
2. Foreground Service 유형(Android 14+ `foregroundServiceType`)과 One UI 배터리 최적화 예외 안내.
3. 자산 원본 URL·용량·SHA256 표(sherpa asr-models, Vosk, FireRed, FSMN, pyannote 변환본 출처), Android `OkHttp`/`HttpURLConnection` + Range 이어받기, tar.bz2 해제 라이브러리(Apache Commons Compress) 라이선스.
4. 앱 전용 저장소에서 sherpa-onnx 가 모델을 읽는지(경로 문자열 기반이라 가능할 것으로 봄 — 실기기 확인).
5. whisper.cpp Android 통합 방법(prebuilt AAR vs NDK 빌드)과 faster-whisper 디코딩 옵션 대응표.
6. ML Kit genai-speech-recognition 1.0.0-alpha2 API 변화(현 alpha1).
7. sherpa-onnx 2.0.1 정적 링크 AAR 배포 여부.
8. ETA 초기 RTF 표 작성(S22 실측·서버 CPU 실측·모델 크기).
