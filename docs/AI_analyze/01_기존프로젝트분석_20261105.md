### 3-6. Feed(오디오 공급 속도) 사실
- `SttCatalog.feeds` = REALTIME 100 ms, D50, D30, D20, D10(배속 = 100/delayMs). 주석의 FAST/MAX는 삭제된 stale 주석.
- 사용 엔진: ML Kit(필수, 10 ms 미만 실측 불가·0 ms는 AUDIO_BUFFER_OVERFLOW), sherpa 스트리밍, Vosk. 오프라인 엔진은 Feed를 받지 않고 최대 속도로 디코딩(feed_ms=-1, tail_ms=wall).
- RTF: 오프라인은 디코딩 시간/음원 길이. 실시간 공급 스트리밍은 wall≈음원 길이라 `tail_ms`로 비교하고, 처리 능력 상한은 "결과가 깨지지 않는 최소 지연/100"으로 구함(기존 설계).
- 새 앱 기본: ML Kit = REALTIME 고정, 스트리밍/Vosk = "사용 안 함(최대 속도)" + REALTIME 선택, 오프라인 = 해당 없음.

### 3-7. 결과·CSV·목록 실행 규칙
- TXT: `<outputRoot>/<엔진>_<모델>_<조건>/<relPath>/<name>.txt`, CSV: `<outputRoot>/<엔진>_<조건>_result.csv`(99열, utf-8-sig), run_meta: `<엔진>_<조건>_run_meta.csv`(key,value 71행).
- 조건 이름(START): `[NS_<ns>_]<VAD토큰>[_SEG10][_EPD_…]`; 목록: `<vad>[_SEG10]`.
- START 언어 자동: `<출력>/<언어 폴더>/…`(서버 v8.4.0과 동일). 목록 실행: `<출력>/<kr|en>/<yyyyMMdd>_<FEED>/[_]…` → **D2에 따라 날짜 폴더 제거 대상**.
- 목록 실행: work 1~3, 오프라인 동시 1(`PLAN_OFFLINE_MAX`), `_plan_progress.csv`(DONE 건너뜀, FAILED/INTERRUPTED 재실행), 발열 SEVERE 이상이면 30 s 간격 최대 20분 대기, 30 s마다 `_plan_memlog.csv`, 종료 이유 `_plan_exits.csv`, 작업 중 폴더 `_` 접두어 → DONE 시 이름 변경, 기존 폴더는 `_stale_…`로 비킴.
- 언어 폴더 규칙(`INPUT_LANG_WORDS`, 서버와 동일): ko ← kr·ko·kor·korea·korean·한국어, en ← en·eng·english·영어; 마디가 같거나 `_<낱말>`로 끝남. 하위 폴더 중 하나라도 판정되면 그 폴더들만, 모르는 폴더는 건너뜀(서버는 묻고 기억). `input_sound/scarlett` 선택 시 `en`·`kr` 하위 폴더가 그대로 인식됨.
- 음원 확장자: mp3, wav, m4a, flac, ogg, aac, mp4, wma, opus.

## 4. 코드 품질 문제·위험 (상위 10)
1. `BatchRunner.run()` 약 920줄 단일 suspend 함수(249~1172). 파이프라인·계측·UI 문자열·권한 설정 화면·preflight 혼재.
2. Activity 결합: `BatchHost.activity`로 DocumentFile·getString·startActivity 호출(BatchRunner 239·297·376 등), `PlanRunner(activity)`(129). ViewModel 재사용 불가.
3. `CancellationException` 삼킴: `catch (e: Exception)`(BatchRunner 656·722·813·1054·1135)이 취소를 ERROR 행으로 기록하고 계속 진행 → 호출자가 `isActive`로 우회 판정.
4. 코루틴 안 `Thread.sleep`(SherpaStreaming 137, Vosk 101, PcmFeeder 89) → 취소 불응, "지금 바로 중지"가 파일 끝까지 대기.
5. 전역·공유 가변 상태: `PlanState.checkedThisProcess`, `GoogleSttSession.sttSessionCount` 외부 리셋(BatchRunner 396), `MainActivity.running`, `BatchRunner.lastCompleted/lastOk/lastFail` 결과 전달.
6. 예외 무로그 삼킴: run_meta 저장 전체 `runCatching`(496~589), CSV flush, finally의 close/저장, `PlanState.newExits`, `MlKitTranscriber.abandonable`.
7. 비원자적 덮어쓰기: `ResultStore.writeBytes`가 delete→createFile(119~121) → flush 중 종료 시 result.csv 소실 가능.
8. CSV 스키마 수동 동기화: `SttRow` 약 100 var ↔ `CSV_HEADER` ↔ `toCsvLine` 순서를 사람이 맞춤(과거 열 밀림 사고 기록).
9. 지식 중복·위치 오류: 언어 전용 모델이 PlanCheck·MainActivity·languageLabel 3곳에 분산, 모델 스피너 인덱스 위치 결합(MainActivity 295~303 vs 383), `VadSegment` 등이 Silero 구현 파일에 있어 역의존.
10. 공용 스토리지·SAF 성능: `MANAGE_EXTERNAL_STORAGE` + `/sdcard/Documents/stt_models`(deprecated API) → 앱 전용 저장소 + 앱 내 다운로드로 전환 필요; `ensureDir`·`writeBytes`가 파일마다 `findFile` 선형 탐색.

기타: `FeedConfig` 주석 stale, MainActivity 머리 주석의 결과 경로 stale, `TenVadDetector` `Native.load` 실패가 배치 시작 시점에야 드러남, 병렬 work가 `MlKitTranscriber` 하나를 공유해 로그 접두어 누락.
