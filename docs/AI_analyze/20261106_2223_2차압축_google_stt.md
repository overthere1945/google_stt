## 7. 일하는 방식에서 배운 것(이 세션)
- **Write 도구가 `﻿` 를 실제 BOM 글자로 바꾼다** → 파일을 쓴 뒤 `grep -rlP '\xEF\xBB\xBF' app/src --include='*.kt'` 로 확인. 커밋 메시지에도 그 글자를 치지 않는다.
- 머리말·변경 표시의 시각은 추측하지 않고 `date +%Y%m%d-%H%M` 값을 쓴다.
- 셸은 zsh 다: 변수는 자동으로 단어 분리되지 않고(`for p in "a b"; set -- $p` 실패), `--include=*.kt` 는 따옴표가 필요하다.
- 여러 줄 수정은 파이썬 스크립트의 "유일 문자열 치환 + assert" 로 한다(원본 순서·위치 유지, 실패하면 바로 드러난다).
- 커밋 하나 400줄 이하 → 넘으면 `a/b`(코드/시험)로 나눈다. 커밋 전 `assembleDebug` + `testDebugUnitTest`.
- 계측 시험은 `./gradlew installDebug installDebugAndroidTest` 뒤 `adb shell am instrument -w [-e class …|-e package …] com.example.google_stt.test/androidx.test.runner.AndroidJUnitRunner`
  (`connectedDebugAndroidTest` 는 끝나면 앱을 지워 SAF 권한·모델이 사라진다).
- 계측 시험 함수가 `runBlocking { … }` 로 끝날 때 마지막 식이 Unit 이 아니면 "should be void" 로 실패한다 → `runBlocking<Unit>`.
- 독립 검토를 맡길 때는 파일 대응표와 다음 단계의 사용 방식만 주고 내 결론은 주지 않는다. 결과는 판단해서 반영하고, 보류한 것은 HANDOFF 에 남긴다.
- 기기 보안 권한 스위치(특수 접근)는 사용자가 직접 켠다. 앱 자신의 실행 중 권한(알림·마이크)은 시험이 UiAutomation 으로 준다(보고에 밝힌다).
