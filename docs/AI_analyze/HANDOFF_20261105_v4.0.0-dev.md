### 구현하며 알게 된 것
- **DocumentFile.createFile 의 MIME 주의**: `application/octet-stream` 으로 만들면 파일 기반 DocumentFile 에서 이름 뒤에 `.bin` 이 붙는다(`x.csv.tmp.bin`).
  확장자 대응표에 없는 MIME(`application/x-google-stt`)을 쓰면 실제 SAF·파일 기반 모두 이름이 그대로다. 실기기 시험에서 발견해 고쳤다.
- **실제 SAF 권한을 계측 시험에서 쓰는 방법**: 앱 화면에서 폴더를 한 번 고르면 권한이 보존된다(`takePersistableUriPermission`). 계측 시험은 그 권한으로
  실제 제공자를 시험한다(권한이 없으면 건너뜀). 단 `connectedDebugAndroidTest` 는 끝나면 앱을 지워 권한도 사라지므로, 평소에는
  `./gradlew installDebug installDebugAndroidTest` 후 `adb shell am instrument -w com.example.google_stt.test/androidx.test.runner.AndroidJUnitRunner` 로 돌린다.
- 원자적 쓰기의 한계: 처음 만드는 파일을 쓰는 도중 죽으면 덜 쓰인 `.tmp` 가 복구 때 정식 이름으로 올라간다. 그런 파일은 중단된 작업의 산출물이라 이어 하기 때 다시 만들어진다(D30).

### 설계와 다르게 한 것·정한 것(구현 세부 — 확인 필요하면 알려 주십시오)

### 구현하며 알게 된 것
- Android 의 `HttpURLConnection` 은 다른 스레드의 `disconnect()` 로 읽기가 바로 깨어난다(중지 26 ms). PC 의 JDK 구현은 읽는 중 `disconnect()` 가 막힐 수 있어 단위 시험에서는 "다시 시도 없이 취소됨" 만 확인한다.
- 계측 시험에서 포그라운드 서비스를 시작할 수 있다(`am instrument` 로 돌린 시험은 백그라운드 시작 제한에 걸리지 않았다). 알림 권한은 시험이 `UiAutomation.grantRuntimePermission` 으로 준다. **앱 화면의 알림 허용 요청은 아직 없다(T7).**
- 네트워크가 끊긴 상태로 여러 자산을 받으면 자산마다 다시 시도(5·15·45초)를 다 쓴다 → 자산 수 × 약 65초. 화면에서 중지할 수 있고, 필요하면 T7-4 에서 "첫 네트워크 실패 뒤 나머지 중단" 을 정한다.
- 받는 중 저장공간이 바닥나면(ENOSPC) 내려받기 도구는 네트워크 오류로 보고 다시 시도한 뒤, 저장소가 이유를 SPACE 로 바꿔 알린다. 시작 전 용량 검사(압축 × 2 + 1 GB)가 먼저 막는다.
