## 4. 열린 문제
| 문제 | 상태 |
|---|---|
| Kotlin 2.4.21 + AGP 9.3.1 Sync | **해소**(T0-2 빌드 성공) |
| Compose BOM 2026.09.00 ↔ material3 1.4.0 | **해소**(BOM POM·의존성 트리로 확인) |
| Vosk zip 용량·SHA256 | PC 다운로드는 됨(풀린 폴더 small-ko 253 MB, small-en 68 MB). zip 크기·해시 기록은 T4-6(`fetch_assets.py`)에서 |
| v3.0.0 빌드·실기기 실행 여부 | **해소**: 이 PC 에서 빌드되고 S24 Ultra 에서 33건 완주 |
| **v3 실행 중 프로세스 멈춤** | en nemotron3.5-560ms × SILERO 1건: `feed_ms` 645 s(기대 66.6 s), `feed_stall_ratio` 9.69, 30초 간격 memlog 가 약 10분 비어 있음, `cpu_ms_delta` 77 s → 앱 프로세스가 약 10분 멈춰 있었다. 원인은 확정하지 못했다(v3 는 포그라운드 서비스·wake lock 이 없다. 화면 꺼짐 또는 앱이 뒤로 간 것으로 추정). 전사문은 정상(1,079자, 같은 엔진 NOVAD 1,078자)이라 TXT 기준으로는 쓸 수 있고, 이 행의 시간 값만 쓰지 않는다. v4 의 D21(specialUse 서비스 + wake lock)이 다루는 문제다 |
| 기준 결과의 RTF | 동시 1 로 잰 값이지만 위 1건처럼 오염 가능 → ETA 초기값으로 쓰지 않는다(8-2 규칙대로 v4 실측 사용) |
| `docs/baseline_v3/` 커밋 | 로컬 커밋만 했다. TXT 는 사용자 녹음의 전사문이다. 원격에 올릴지는 push 전에 사용자가 정한다 |
| JDK | Gradle 데몬은 toolchain 21(`gradle-daemon-jvm.properties`), 셸 `java` 는 JBR 25. 문서의 "JDK 17" 은 컴파일 대상(jvmTarget 17)을 뜻한다. 빌드 문제 없음 |

## 5. 실기기 시험 방법(Claude Code 가 직접 하는 절차)
- 기기: `adb devices` → `R3CX804DZTW`(SM-S928N). 확인된 동작: 빌드 → `adb install -r` → `am start` → `uiautomator dump`(화면 요소·좌표) → `input tap`/`swipe` → `logcat -s GoogleStt` → `screencap` → `adb pull`.
- SAF 폴더 선택기도 위 방법으로 조작된다(입력·출력 폴더 선택, "이 폴더 사용" → "허용").
- 사용자가 직접 해야 하는 것: 기기 보안 권한 스위치(v3 의 '모든 파일에 대한 접근'). v4 는 이 권한을 쓰지 않는다.
- `connectedDebugAndroidTest` 는 끝나면 앱을 **지운다**(SAF 권한·앱 전용 저장소도 함께 사라짐). 모델을 앱 전용 저장소에 두는 WP4 이후에는 계측 시험 뒤 모델을 다시 받아야 하므로, 시험용 모델 준비 방법을 T4/T5 에서 정해야 한다.
- 폰에 v3.0.0 을 다시 깔려면: `git switch --detach v3.0.0` 으로 빌드하거나 보관한 APK 를 `adb install -r -d`(디버그 앱은 낮은 판으로 덮어쓰기 가능).
- 폰 현재 상태: 앱 4.0.0-dev(화면은 v3 그대로) 설치, `Documents/stt_models/`(기준 모델 7종, 약 2.4 GB), `Documents/input_sound/baseline/`, `Documents/stt_plan/plan_baseline_v3.csv`, `Documents/output/baseline_v3/` 남아 있음.
- PC: `stt_models/`(git 제외, 2.4 GB), `app/src/androidTest/assets/audio/{kr,en}/…/01.wav`(git 제외).
